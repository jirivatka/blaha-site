Support

Ask a question or report a problem in the support forum. It is open to everyone — a GitHub account is all you need, and you do not need a Vikunja server to post.

⚠️ Never post an API token, a password or a server address you would rather keep private. Not in a screenshot, not in a log, not "with a few characters removed". If a token has been shared anywhere, delete it in Vikunja under Settings ▸ API Tokens and make a new one.

Blaha needs a Vikunja server — or the demo

Blaha is a client, not a service. Your tasks live on a Vikunja server that you run, or on Vikunja Cloud; Blaha talks to that and to nothing else.

To look around without any of that, tap Try the demo on the first screen. The demo is a Vikunja that runs on the device itself — sample projects, tasks and calendar events, with writes that behave exactly as they would against a real server. It needs no account and no network. Leave it under Preferences ▸ Server.

Connecting

The address
The address of the Vikunja itself, for example https://tasks.example.com — not the /api/v1 path underneath it. It must be HTTPS. A plain http:// address will not connect: iOS and macOS block unencrypted connections, and Blaha asks for no exception to that.
An API token (recommended)
Make it in Vikunja under Settings ▸ API Tokens, with read and write on Tasks, Labels and Projects. A token does not expire, which makes it the steadier of the two methods — and on Vikunja Cloud it is the only one that works, because Cloud does not accept a username and password over the API at all. Blaha keeps the token in the system Keychain.
Username and password
An alternative for a server you host yourself. If the account has two-factor authentication, Blaha asks for the one-time code as part of signing in.
A certificate the device does not trust
A self-signed certificate will be refused, as it would be in Safari. Use a certificate from a certificate authority — Let's Encrypt is free — or install and trust your own CA on the device first.

Connected, but something is missing

A project's tasks do not appear
Check that the token carries read on Tasks and on Projects. A token with Projects only lists the projects and nothing inside them.
Nothing can be edited
The token needs write as well as read. Blaha will queue the change and keep retrying, so edits appear to stick and then come back — see the outbox, below.
A shared project is missing
Blaha shows what the account you signed in as can see. If a project was shared with a different account, sign in as that one — or, with the unlock, add it as a second account.

Offline, and the outbox

Blaha keeps working without a connection: the last sync is cached, and anything you change is queued and sent when the server is reachable again. Nothing is silently dropped, and a queued change is not lost by closing the app.

If something stays queued, it is usually the server refusing it — a permission on the token, or a project that no longer exists.

Calendar and reminders

Calendar events
Blaha reads the calendars already on your device, through the system's own permission. It never writes to them, and it sends nothing about them anywhere. In the demo, the events are the demo's own — no calendar permission is asked for and nothing of yours is read.
Reminders arrive late, or not at all
Reminders are scheduled locally by your device, so they need notification permission, which Blaha asks for where a reminder is set. On a Mac, check System Settings ▸ Notifications ▸ Blaha: with the style set to Banners an alert disappears after a few seconds, while Alerts stays until it is dismissed.

The unlock

What is free
Forecast, Tasks, Calendar, Projects, Done, capture, the share extension and the widgets — including defer dates.
What the unlock adds
Blocked, Review, Perspectives and multiple accounts. One payment, no subscription.
The 7-day trial
Everything is open for seven days from first launch. When it ends, the four paid screens say so rather than pretending they were never there.
You already bought it, on another device
Use Restore on the purchase screen. The unlock belongs to your Apple Account, so it carries across your iPhone, iPad and Mac at no extra cost.

Your data

Blaha has no backend. Your tasks go to your server and nowhere else, there is no analytics and no crash reporter, and the only account involved is the one you already have. The privacy policy says this at length, and to delete everything Blaha holds it is enough to delete the app — the tasks themselves live on your server and are yours to remove there.

What helps a question get answered

  • your device and OS version, and whether it is the iPhone, iPad or Mac app
  • your Vikunja version, and whether it is self-hosted or Cloud
  • what you expected to see, and what appeared instead
  • whether the same thing happens in the demo — that separates the app from the server in one step
